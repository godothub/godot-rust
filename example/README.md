# Hello Rust

这是 `godot-rust` 的标准 Godot + Cargo 示例项目，也是插件发布包的来源。

## 仓库内运行

在仓库根目录构建并装配当前平台的开发插件：

```sh
python3 tools/stage_example_plugin.py
```

然后用 Godot 4.4 或更高版本打开本目录。示例已启用
`Project > Project Settings > Plugins > godot-rust`。顶部 `Project > Tools`
菜单中提供：

- `Rust: Project Status`
- `Rust: Check`
- `Rust: Build`

## 创建 Rust 脚本

1. 在场景树中选择节点，点击 Godot 自带的“挂载脚本”按钮。
2. 把语言切换为 `Rust`。
3. 把脚本保存到 `res://src/scripts/` 或其子目录。
4. 点击“创建”。插件会根据节点基类生成 Rust 类型，并保存 `.rs` 文件和
   Godot Resource UID。
5. 保存后插件会等待 400ms；期间发生的连续修改会合并为一次 Cargo Check。
   插件发现新脚本、更新 Cargo 模块索引，再调用本机 Cargo，不需要打开终端。

`src/scripts/mod.rs` 是插件生成的编译入口，不需要手工添加 `mod`。插件只会
覆盖带有 `@generated by godot-rust` 文件头的索引，不会替换自行维护的
`mod.rs`。脚本可以放在多级子目录中；发现顺序、模块名和注册顺序保持稳定。

编辑器底部的 `Rust` 面板显示检查和构建状态，并提供 `Check`、`Build` 和
`Clear`。Cargo 的错误、警告、错误码和主源码位置会显示在列表中；双击带有
项目源码位置的诊断即可打开对应 `.rs` 文件并跳到行列。自动检查失败时会保留
诊断；下一次检查成功后会清除已经过期的内容。

## 在 Godot 中编辑 Rust

打开 `.rs` 脚本后，Godot 自带的脚本编辑器会直接提供：

- Rust 2024 关键字、控制流关键字和基础数值类型着色。
- `//`、`/* ... */` 普通注释和 `///`、`//!`、`/** ... */`、
  `/*! ... */` 文档注释着色。
- 普通字符串、字节字符串、C 字符串和常见原始字符串的字符串区域着色。
- 编辑器原有的括号补全、行号、代码折叠、搜索、书签和多光标功能。
- `Ctrl+I`（macOS 为 `Command+I`）自动缩进。

自动缩进以 Rust 的花括号层级为依据，会忽略普通字符串、字符、任意 `#`
数量的原始字符串、行注释和可嵌套块注释中的花括号。它只改动当前选择的行；
没有选择时改动整个文件。即使源码正在输入、字符串暂未闭合，也会返回完整
源码，不会把编辑内容替换为空。

Godot 的标准高亮器只接受固定的字符串起止符，因此带有多个 `#` 且内容本身
包含双引号的复杂原始字符串可能只得到近似着色；这不影响 Cargo 编译、诊断或
运行结果。字符字面量不会被注册为单引号字符串区域，以免把 `'static` 等 Rust
生命周期错误地涂成字符串。

函数跳转使用容错 Rust 词法扫描，会跳过注释、普通字符串、原始字符串和字符
字面量中的伪函数，并能找到所有 `#[script] impl` 内的方法。

## 从 Godot 连接信号

在场景树中选择信号源节点，打开 `Node > Signals`，按 Godot 原有流程选择信号
和目标节点并点击“连接”。目标节点挂载 Rust 脚本时，Godot 会直接打开对应的
`.rs` 文件，并生成可编译的类型化回调：

```rust
#[script]
impl Hello {
    #[func]
    fn _on_child_entered_tree(&mut self, _node: Option<ObjectRef<Node>>) {
        // TODO: Handle the connected Godot signal.
    }
}
```

生成器会读取信号参数名称和 Godot 类型。Godot 的标量、文本、数学类型、
动态容器、Callable、Signal、RID、Packed Array 以及 Object 类都会转换为
对应的 Rust 类型；Object 参数使用可空的 `Option<ObjectRef<T>>`。参数名会
自动避开 Rust 关键字和重复名称。

每次连接都可以追加一个独立的 `#[script] impl`，SDK 会在编译期把同一脚本类型
的多个 impl 聚合为一张稳定分发表，因此不需要手工移动回调，也不会在运行时
解析源码。未来 Godot 版本出现未知 Variant 类型时不会生成错误签名；编辑器会
在源码和输出中写明具体类型，等待 SDK 增加对应的安全表示。

Godot 创建的最小脚本与平常的节点脚本写法一致：

```rust
use godot_rs::prelude::*;

#[script(base = Node2D)]
pub struct Player {
    #[export(default = 240.0)]
    speed: f64,
}

#[script]
impl Player {
    fn _ready(&mut self) -> EngineResult<()> {
        let base = self.base();
        base.set_process(true)?;
        godot_print!(
            "Player {} is ready; processing={}",
            base.get_instance_id()?,
            base.is_processing()?
        );
        Ok(())
    }

    #[func]
    fn double_speed(&self) -> f64 {
        self.speed * 2.0
    }
}
```

`#[script(base = Node2D)]` 对应 Godot 的节点基类，`_ready` 等生命周期方法直接
由引擎调用，`#[export]` 出现在 Inspector，`#[func]` 可由 Godot 调用。宏在
编译期生成描述符和分发表，运行时不会解析 Rust 源码；常用标量直接经过稳定
C ABI 传递。高频逻辑应保留在 Rust 的类型化字段和方法中，只在 Godot 边界
转换数据。

同一个类型可以按职责拆成多个 `#[script] impl Player`。生命周期、普通方法、
RPC 和由信号面板创建的回调会自动合并；方法名、稳定 ID 或生命周期槽重复时，
构建会明确失败，不会按源码顺序悄悄覆盖。

## 全局类、自定义 Resource 与脚本继承

`class_name` 让 Rust 脚本进入 Godot 的全局脚本类列表。节点脚本可以直接用于
“创建节点”和类型提示，`base = Resource` 的脚本可以作为自定义 Resource：
首次 Rust Build 成功后，插件会在当前编辑器会话刷新这些类型，无需重启 Godot。

```rust
#[script(base = Resource, class_name = WeaponStats)]
pub struct WeaponStats {
    #[export(default = 10)]
    damage: i64,
}
```

Rust 脚本通过规范的 `res://` 路径继承另一个 Rust 脚本。派生脚本会获得父脚本
的 Inspector 字段、方法和信号；派生脚本没有实现某个生命周期时，Host 会调用
继承链中最近的实现：

```rust
#[script(
    base = Node,
    extends = "res://src/scripts/base_actor.rs",
    class_name = Player
)]
pub struct Player {
    #[export(default = 100)]
    health: i64,
}
```

父脚本必须属于同一个项目模块，并使用相同的 Godot `base`。循环继承、缺失的
父脚本、重复字段和不一致的 Godot 基类都会在模块加载时被拒绝。派生方法与父
方法同名时使用派生实现。需要显式调用继承链中的下一层实现时，直接使用
`call_super`；参数和返回值沿用普通 `#[func]` 的类型化编码，可连续调用多层父
脚本，也不会再次进入当前派生实现：

```rust
#[script]
impl Player {
    fn _ready(&mut self) -> EngineResult<()> {
        self.call_super::<(), _>("_ready", ())?;
        Ok(())
    }

    #[func]
    fn display_name(&self, suffix: String) -> String {
        match self.call_super::<String, _>("display_name", (suffix,)) {
            Ok(base_name) => format!("[Player] {base_name}"),
            Err(error) => {
                godot_warn!("base display_name failed: {error}");
                "[Player]".to_owned()
            }
        }
    }
}
```

生命周期方法也通过同一个入口调用父脚本；`()` 表示没有参数或没有返回值。
普通父方法声明的尾随 `#[default(...)]` 也会生效，因此可以只传必需参数。
如果父脚本不存在对应实现、参数类型不匹配或父回调失败，错误会通过
`EngineResult` 返回并进入 Godot Debugger，不会再次调用当前派生方法。

## 异步任务

`spawn` 在 Godot 主线程上运行无需 `Send` 的 Rust Future，适合把一段工作拆到
后续帧，同时继续安全使用 Script Mode 的主线程 API：

```rust
fn _ready(&mut self) -> EngineResult<()> {
    let owner_id = self.base().get_instance_id()?;
    let task = spawn(async move {
        next_frame().await;
        godot_print!("object {owner_id} reached the next frame");
    });
    let _task_id = task.id();
    Ok(())
}
```

任务每帧由 Host 协作轮询，不会隐式创建线程。任务 Panic 只会结束对应任务；
`TaskHandle::cancel()` 可请求取消。热重载切换代际和模块关闭时会取消该代际尚未
完成的任务。Future 必须拥有其捕获值并满足 `'static`，不能把 `&mut self` 保留
到当前回调结束之后。

## 安全热重载

编辑器中的 Rust Build 成功并发布新的 Last Known Good 后，Host 会在主线程帧
边界加载候选模块。代码与脚本结构兼容时，所有现有实例会先创建候选状态，再按
以下规则迁移，全部成功后才一次性切换：

- `#[reload(persist)]` 始终尝试保留支持传输的字段；
- Inspector 中保存的 `#[export]` 字段默认保留；
- `#[reload(skip)]` 和普通非导出字段重新使用构造默认值；
- Node 字段在迁移后根据当前场景重新解析；
- 字段类型、方法签名、继承关系或反射结构变化时保留旧代际，并提示重新运行场景。

候选加载、Schema 校验、状态复制或 Node 解析任何一步失败，都不会修改活动实例。
旧动态库会一直保留到旧状态和它创建的所有权值全部释放。

## Extension Mode 原生类

直接注册原生类的项目使用简短的模式名：

```toml
[package.metadata.godot-rust]
mode = "extension"
godot = "4.4"
```

Extension Mode 直接把 Rust 类型注册到 ClassDB，不经过 Script Host。普通方法、
属性、信号和 Godot 虚方法分别使用类型化注册器；虚方法入口由当前 Godot API
自动生成，调用者不填写 Method Hash，也不能把错误签名注册给引擎：

```rust
use godot_rs::engine::native_virtual;
use godot_rs::native::*;
use godot_rs::prelude::*;

struct Mover {
    base: Base<Node2D>,
    speed: f64,
}

impl Mover {
    fn process(&mut self, delta: f64) {
        let _ = self.base.translate(Vector2::new(self.speed * delta, 0.0));
    }

    fn speed(&self) -> f64 { self.speed }
    fn set_speed(&mut self, value: f64) { self.speed = value; }
}

impl NativeClass for Mover {
    type Base = Node2D;
    const CLASS_NAME: &'static str = "Mover";

    fn init(base: Base<Node2D>) -> Self {
        Self { base, speed: 120.0 }
    }

    fn register_virtuals(
        registrar: &mut NativeVirtualRegistrar<'_, Self>,
    ) -> NativeResult {
        native_virtual::node::_process(registrar, Self::process)?;
        Ok(())
    }

    fn register_methods(
        registrar: &mut ClassRegistrar<'_, Self>,
    ) -> NativeResult {
        registrar.property("speed", Self::speed, Self::set_speed)?;
        Ok(())
    }
}
```

`NativeClass` 还支持 Inspector Hint/Usage、属性分组、动态属性列表、属性回退值、
属性校验、自定义 `str(object)`、通知、类型化信号、RPC 元数据，以及抽象、虚拟、
暴露、仅运行时和自定义图标等 ClassDB 标志。常用 Godot API 仍通过
`self.base()`、构造函数、Singleton、Builtin 和 Utility 的生成接口调用。

## Extension Mode 热重载

编辑器中的 Rust Build 会生成新的不可变动态库并立即请求 Godot 重载。已存在的
Godot Object 和注册为属性的状态会保留；普通 Rust 字段会重新使用 `init` 的值。
需要重建缓存、节点引用或临时状态时，实现专用回调：

```rust
fn on_extension_reloaded(&mut self) -> NativeResult {
    self.rebuild_cache();
    Ok(())
}
```

属性恢复完成后才会调用该回调，`_ready` 不会重复执行。新动态库加载或初始化
失败时，插件自动恢复并重新加载上一代；基类等 Godot 无法在线变更的结构变化会
明确提示重启编辑器。首次构建失败时会安全撤销候选描述文件，不会把失败产物留给
下一次编辑器启动。

## rust-analyzer、外部编辑器与源码调试

首次配置 Cargo 项目时，如果对应文件不存在，插件会创建：

- `.vscode/settings.json`：连接项目 Cargo.toml、启用 Clippy，并隔离分析输出；
- `.vscode/tasks.json`：Cargo Check、Build 和 Test；
- `.vscode/launch.json`：CodeLLDB 与 GDB 附加配置。

已有文件不会被覆盖。VS Code、Zed 和 RustRover 会读取同一个 Cargo 项目及
`.cargo/config.toml` 中的 Godot API 选择。默认情况下，Rust 脚本遵循 Godot 的
“文本编辑器 > 外部”设置；未启用外部编辑器时仍可使用 Godot 内置脚本编辑器。
如需为 Rust 单独指定编辑器，可把 `GODOT_RS_EXTERNAL_EDITOR` 设置为可信编辑器
可执行文件的绝对路径。Godot 中的行列会一起传递。

调试脚本时先以开发配置执行 Rust Build，再从 IDE 附加到正在运行的 Godot
进程。项目模块保留开发调试信息，因此断点可以落在 `.rs` 回调中；Release 导出
仍使用优化构建。热重载后动态库地址会改变，调试器需要重新解析新模块，必要时
重新附加一次。

## 方法默认参数与可变参数

`#[func]` 使用 `#[default(...)]` 声明 Godot 可见的尾随默认参数。默认值仍是
对应 Rust 类型，不需要手写 `Variant`，Godot 的方法列表、脚本资源元数据和
动态调用都会看到相同的默认值：

```rust
#[script]
impl Player {
    #[func]
    fn add_score(
        &mut self,
        amount: i64,
        #[default(1)] multiplier: i64,
        #[default(String::from("gameplay"))] source: String,
    ) -> i64 {
        let gained = amount * multiplier;
        godot_print!("{source}: +{gained}");
        gained
    }
}
```

和 Godot 自身的方法规则一致，第一个默认参数之后的所有固定参数都必须有默认
值。宏会在编译期拒绝中间缺失的默认值、生命周期回调默认值，以及给可变参数
本身设置默认值。默认表达式会在模块加载校验和 Godot 反射时执行，因此应保持
确定性，不要依赖当前场景节点或产生业务副作用；对象默认值只能为空。

最后一个参数写成共享的 `&[Variant]` 时，方法会自动成为 Godot 可变参数方法：

```rust
#[script]
impl Player {
    #[func]
    fn record(
        &self,
        #[default(String::from("general"))] category: String,
        values: &[Variant],
    ) -> i64 {
        godot_print!("{category}: {} values", values.len());
        values.len() as i64
    }
}
```

Godot 只把 `category` 视为固定参数，其后的任意值按原有 Godot 类型进入
`values`。固定参数继续走类型化转换；只有实际使用可变参数时才创建临时
`Variant` 列表，列表只在本次同步调用期间存在。

## Vector2、Vector2i、Vector3、Vector3i 与 Color

脚本可以像写 Godot 脚本一样直接使用 `Vector2`、`Vector2i`、`Vector3`、
`Vector3i` 和 `Color`。它们可用于普通 Rust 字段、`#[export]`、`#[func]`
参数和返回值，以及类型化信号：

```rust
#[script(base = Node2D)]
pub struct Mover {
    #[export(default = Vector2::new(240.0, 0.0), group = "Movement")]
    velocity: Vector2,

    #[export(default = Vector3::new(0.0, 1.0, 0.0))]
    target_position: Vector3,

    #[export(default = Vector2i::new(4, -6))]
    grid_cell: Vector2i,

    #[export(default = Color::rgba(0.2, 0.6, 1.0, 1.0), no_alpha)]
    tint: Color,

    #[signal(args(position, tint))]
    moved: Signal<(Vector2, Color)>,
}

#[script]
impl Mover {
    #[func]
    fn advance(&mut self, position: Vector2, delta: f32) -> Vector2 {
        let next = position + self.velocity * delta;
        self.moved.emit((next, self.tint));
        next
    }
}
```

`Vector2` 和 `Vector3` 提供 Godot 习惯的方向常量、点积、长度、归一化、线性
插值和常用算术运算；`Vector3` 还提供叉积。`Vector2i` 和 `Vector3i` 使用精确的
`i32` 分量，提供方向常量、点积与整数算术，适合网格坐标、单元索引和体素位置。
`Color` 提供 RGBA 构造、透明度修改、线性插值和逐通道相乘。字段保持公开组件，
例如 `velocity.x`、`grid_cell.y` 和 `tint.a`，不需要 getter 包装。`no_alpha`
只适用于 `Color`，用于在 Inspector 隐藏 Alpha 编辑。

浮点向量与颜色使用紧凑的 `f32` 分量，整数向量使用紧凑的 `i32` 分量；高频
运算发生在项目模块内部，不需要堆分配或引擎调用。跨动态库时使用固定布局的
紧凑值传输；只有进入或离开 Godot 时才转换为 Variant。Host 通过 Godot 官方的
命名组件接口完成转换，不读取 Godot 内部 `real_t` 内存布局。

导出的数学字段支持 Inspector 默认值、属性还原和场景保存恢复。Godot 中可用
`Vector2(...)`、`Vector2i(...)`、`Vector3(...)`、`Vector3i(...)`、`Color(...)`
直接调用相应的 Rust 方法并接收 Signal，不需要手工序列化数组或字典。

由官方 API 生成的 Godot 方法同样支持这些类型和 `String`。字符串参数以 `&str`
同步借用，返回值复制为标准 Rust `String`；向量和颜色通过精确的 ptrcall 原生
存储传递。因此 `base.set_position(position)?`、`label.set_text("Ready")?` 或
`grid.set_size(Vector2i::new(32, 32))?` 都不需要手写 Variant 转换。

## String、Inspector 与信号

脚本直接使用标准 Rust `String`，不需要包装类型。`#[export]` 的默认值和提示
会显示在 Godot Inspector 中，`#[func]` 的字符串参数与返回值可由 GDScript
直接调用，`Signal` 的参数名称和类型也会出现在 Godot 的脚本元数据中：

```rust
#[script(base = Node)]
pub struct Greeter {
    #[export(default = "你好", group = "Text", multiline)]
    message: String,

    #[export(default = "res://main.tscn", file("*.tscn"))]
    scene_path: String,

    #[signal(args(message))]
    greeted: Signal<(String,)>,
}

#[script]
impl Greeter {
    #[func]
    fn greet(&mut self, name: String) -> String {
        let message = format!("{}，{name}", self.message);
        self.greeted.emit((message.clone(),));
        message
    }
}
```

从 Godot 传入 Rust 的字符串只在同步调用期间借用，SDK 会在进入用户方法前
复制成正常的 Rust `String`。Rust 返回的字符串由项目模块拥有，Host 在复制成
Godot `String` 后立即通过对应模块代际释放；信号参数在同步发射期间借用，避免
再做一次不必要的 Rust 字符串复制。标量仍走固定大小、无分配的 ABI。这样既
保持 Godot 常用写法，也把跨动态库的内存所有权限制在明确边界内。

String 导出字段会像其他 `#[export]` 字段一样随场景保存和恢复。`multiline`
用于多行文本，`file("*.tscn")` 用于带文件筛选条件的路径输入。尚未支持的
Variant 类型会在编译期报错，不会在运行时悄悄转换。

## 调用 Godot API

`self.base()` 对应当前脚本所挂载的 Godot 对象。插件会按项目选择的最低
Godot 4.4、4.5、4.6 或 4.7 API 生成类型安全的 Rust 方法，并根据 ClassDB
继承关系自动提供父类方法：

```rust
fn _ready(&mut self) -> EngineResult<()> {
    let base = self.base();
    base.set_process(false)?;
    let was_disabled = !base.is_processing()?;
    base.set_process(true)?;

    let parent: Option<ObjectRef<Node>> = base.get_parent()?;
    godot_print!(
        "owner={}, disabled={}, has_parent={}",
        base.get_instance_id()?,
        was_disabled,
        parent.is_some()
    );
    Ok(())
}
```

方法参数和返回值保持 Rust 的精确类型，例如 `int32` 使用 `i32`、`uint64`
使用 `u64`、Godot `float` 使用 `f32`。普通对象使用 `ObjectRef<T>`，节点字段
仍可使用含义更直接的 `NodeRef<T>`；两者都只在项目模块中保存 Godot Object
ID，不会把引擎内存指针交给脚本。Host 在调用时重新解析对象、校验 ClassDB
类型和 Method Hash，已经释放的对象会返回
`EngineErrorKind::StaleObject`。

每个受支持版本中，具有安全 C ABI 表示的普通方法、静态方法、可变参数方法和
虚方法都会生成。`const void*`、`void*`、引擎内部结构体指针和扩展初始化函数
指针会被明确归类为原始指针 API，不会伪装成整数、`Variant` 或可长期保存的
Rust 引用；这些指针只对实现底层 Godot 扩展服务器的代码有意义，不能安全穿过
Script Mode 的项目模块边界。质量门禁要求除此之外的类型缺口始终为零。

### 单例、构造、Utility、Builtin、常量与引擎信号

除 Object 类方法外，官方 API 中其余可安全调用的入口也会按所选 Godot 版本
自动生成，并由 `godot_rs::prelude::*` 统一导入：

```rust
fn _ready(&mut self) -> EngineResult<()> {
    let input = Input::singleton()?;
    if input.is_action_pressed("ui_accept", false)? {
        godot_print!("random value: {}", utility::randf()?);
    }

    let white = builtin::color::constant_white()?;
    let normalized =
        builtin::vector2::normalized(&Vector2::new(3.0, 4.0))?;

    let timer = Timer::new_godot()?;
    let timeout: Signal<()> = timer.signal_timeout()?;
    godot_print!(
        "color={white:?}, normalized={normalized:?}, signal={}",
        timeout.name()
    );
    Ok(())
}
```

- 单例使用 `Input::singleton()` 这类关联函数。
- 可实例化的 Object 类使用 `Timer::new_godot()`；RefCounted 类会返回
  `GodotRef<T>`，其他类返回 `ObjectRef<T>`。
- 全局函数位于 `utility`，例如 `utility::randf()`。
- Builtin 的完整官方接口位于 `builtin::<类型>`，包括构造、方法、运算符、
  成员、索引、键访问和常量。
- Builtin 实例还会获得 `Vector2BuiltinApi` 这类扩展 Trait，其方法统一使用
  `godot_` 前缀，避免覆盖 Rust 标准库和类型本身的同名方法。SDK 已经内联实现
  的数学操作不会跨越 Host 边界；需要 Godot 精确语义或完整重载时，可调用
  `value.godot_normalized()` 或直接使用 `builtin::<类型>` 模块。
- 引擎信号通过 `TimerSignals` 这类自动生成 Trait 提供类型化句柄，参数元组与
  官方信号声明一致。
- 全局常量位于 `global_constants`，类常量使用 `Class::CONSTANT`，Builtin
  常量通过 `builtin::<类型>::constant_<名称>()` 读取。

上述入口与普通类方法共用同一套经过校验的 Host 调用协议。项目模块不会接触
Godot 的对象指针、Builtin 原生内存布局或析构函数；构造后的对象会执行引擎
要求的初始化通知，返回值和可变 Builtin 接收者按明确的所有权规则更新。

### RID 与引用计数对象

Godot `RID` 在 Rust 中写作 `Rid`。它是 RenderingServer、PhysicsServer、
NavigationServer 等服务器资源的不透明句柄，可以直接用于 `#[func]` 参数和
返回值、类型化信号以及生成的 Godot API：

```rust
#[signal(args(canvas))]
canvas_ready: Signal<(Rid,)>,

fn _ready(&mut self) -> EngineResult<()> {
    let Some(viewport) = self.base().get_viewport()? else {
        return Ok(());
    };
    let Some(world) = viewport.find_world_2d()? else {
        return Ok(());
    };
    let canvas = world.get_canvas()?;
    if canvas.is_valid() {
        self.canvas_ready.emit((canvas,));
    }
    Ok(())
}

#[func]
fn echo_rid(&self, resource: Rid) -> Rid {
    resource
}
```

`Rid` 可复制、比较和作为 HashMap 键；`Rid::INVALID` 表示 Godot 的空句柄，
`is_valid()` 检查数值是否非零，`id()` 适合诊断输出。复制 `Rid` 不会延长
服务器资源生命周期，也不应根据 `id()` 推断资源类型或引擎内部布局。

上例中的 `find_world_2d()` 返回
`Option<GodotRef<World2D>>`，因为 `World2D` 继承自 Godot
`RefCounted`。`GodotRef<T>` 拥有对应的原生引用；克隆它会共享同一份所有权，
最后一个 Rust 克隆离开作用域时，Host 通过 Godot 官方 Ref 接口释放引用。
因此用户不需要调用 `reference()`、`unreference()` 或手工销毁资源。需要把它
传给只借用普通对象的 API 时，使用 `world.object_ref()`。

`ObjectRef<T>` 与 `GodotRef<T>` 都不会把引擎指针交给项目模块。前者只表示
可失效的对象身份，适合 Node 等由场景树拥有的对象；后者用于生成 API 返回的
引用计数对象，并保证它在 Rust 使用期间保持存活。

### ObjectRef 与脚本方法

`#[func]` 也可以直接接收和返回带类型的 Godot 对象：

```rust
#[func]
fn choose_target(
    &self,
    target: Option<ObjectRef<Node>>,
) -> Option<ObjectRef<Node>> {
    target
}
```

Godot 的方法元数据会同时得到 `Object` 类型和具体的 `Node` 类名。调用进入
Rust 前会校验对象仍然有效且继承自声明的 ClassDB 类；返回时保留对象身份，
`None` 与 Godot 的 `null` 双向对应。

普通 Godot 方法以 `EngineResult<T>` 返回错误。生命周期方法可以直接返回
`EngineResult<()>`，因此可以使用 `?`；也可以在 `ScriptResult<()>` 中使用
`?`，SDK 会把引擎错误转换为适合脚本回调的错误类别。

### 回调错误与实例隔离

`ScriptResult` 返回的错误、引擎调用错误和未处理的 Rust panic 会显示在 Godot
调试器与 Output 中，并带有 `.rs` 资源路径和回调名称。项目模块会在 ABI 边界
捕获 panic，不允许它展开到 Godot。失败的方法向 Godot 返回 `Nil`，不会再被
误报为“函数不存在”。

Host 为每个脚本实例独立记录连续失败：第一次失败立即报告，后续相同阶段的
重复信息会被抑制；任意一次成功回调会清零计数。连续三次回调失败会停用该
实例，panic 会立即停用该实例。停用后不再执行该实例的 Rust 回调或属性访问，
但挂载同一脚本的其他节点仍可正常运行。重新创建节点或重新挂载脚本即可获得
新实例。panic 仍表示程序缺陷，不应作为普通分支控制使用。

## 获取场景节点

使用 `#[node("路径")]` 声明场景节点后，不需要在 `_ready` 中手动调用
`get_node`。路径使用 Godot 原生 `NodePath` 规则，字段类型同时限定节点类型：

```rust
#[script(base = Node2D)]
pub struct Player {
    #[node("%Sprite")]
    sprite: NodeRef<AnimatedSprite2D>,

    #[node("../Camera", optional)]
    camera: Option<NodeRef<Camera2D>>,
}

#[script]
impl Player {
    fn _ready(&mut self) -> EngineResult<()> {
        self.sprite.set_speed_scale(1.0)?;
        if let Some(camera) = self.camera {
            godot_print!("Camera object ID: {}", camera.get_instance_id()?);
        }
        Ok(())
    }
}
```

Host 会在 `_ready` 之前解析这些字段；即使脚本没有自行声明 `_ready`，节点字段
也会自动完成初始化。必选节点不存在、路径指向的节点类型与 `NodeRef<T>` 不符，
或者脚本挂载对象不是 `Node` 时，Godot 输出会指出字段名、路径和预期类型。
带 `optional` 的字段在节点不存在时得到 `None`，但节点存在而类型错误仍会报告
错误，避免把场景配置问题悄悄隐藏起来。

`Rust: Build` 会调用用户本机 Cargo，校验项目模块，发布 Last Known Good，
并在 `.godot/rust/build-receipt.json` 写入本次成功构建的记录。该文件由插件
管理，不需要提交到 Git。

按 F5 或 F6 时，Godot 会调用插件的构建回调。插件先校验构建记录：Cargo
报告的 Rust 输入、脚本和对应的 `.uid` 文件、Cargo 清单与锁文件、Cargo 和
rustup 配置、构建环境摘要、Cargo/rustc 版本、插件内置构建工具以及 Last
Known Good 模块都没有变化时，直接使用上次成功构建，不再启动 Cargo。记录
缺失、损坏或任一输入变化时，插件同步执行增量构建和独立模块校验；只有成功
发布 Last Known Good 才允许项目启动。

F5/F6 的同步构建失败时，插件会阻止启动，修复诊断后再次运行即可。后台构建
失败时，当前编辑器继续运行上一个 Last Known Good，不会加载失败产物。Cargo
会按标准行为解析和下载尚未缓存的依赖，不需要预先执行 `cargo fetch` 或
`cargo build`。

新启动的项目进程会发现刚发布的 Last Known Good。当前编辑器进程也会监视新
代际，并在主线程帧边界执行 Schema 校验和状态迁移；成功后直接切换 Rust 代码，
失败则保留上一个代际。只有字段、方法和继承结构保持兼容时才允许热重载，结构
变化需要重新运行场景。

## 导出游戏

直接打开 Godot 的 `Project > Export`，选择平台后使用原有的“Export Project”
或“Export All”即可。插件会在导出开始时自动完成以下操作：

- 根据 Godot 预设中的操作系统、架构以及 Debug/Release 模式调用用户本机 Cargo；
- 自动解析和下载尚未缓存的 Cargo 依赖，无需先执行 `cargo fetch` 或
  `cargo build`；
- 对生成的项目动态库执行独立 ABI 校验，失败时阻止导出；
- 把校验成功的模块交给 Godot 导出器，由 Godot 放到可执行文件旁并纳入平台
  原有的复制与签名流程；
- 在游戏启动后从导出包读取 Rust Script 资源，并加载随游戏交付的项目模块。

Debug 导出使用 Cargo Dev Profile，Release 导出使用 Cargo Release Profile。
两者分别保存在 `.godot/rust/exports/<平台>/<模式>/`，不会覆盖编辑器运行所用的
Last Known Good。Cargo 编译错误会继续显示在 Rust 面板中，缺少目标标准库、
ABI 校验失败或模块文件缺失都会让导出明确失败，不会生成假成功的游戏包。

支持的目标包括 Linux x86_64/ARM64、macOS x86_64/ARM64/Universal、Windows
x86_64、Android ARMv7/ARM64/x86/x86_64、iOS ARM64 真机与 ARM64/x86_64
Simulator，以及 Web。Script Mode 与 Extension Mode 使用相同的目标选择和
失败关闭校验；iOS 项目模块与 Host 使用同时包含真机和模拟器切片的
XCFramework，Web 使用 Godot 的动态扩展模板。

桌面目标通常直接使用本机工具链。Android 需要 Android SDK、NDK 和对应 Rust
Target；iOS 需要 Xcode；Web 需要与目标 Godot 模板匹配的 Emscripten 工具链。
缺少链接器、标准库、模板或签名配置时会在导出阶段明确失败。macOS Universal
会分别构建两个 Rust Target 并合并为一个动态库；首次使用前确保两个标准库都
已安装：

```sh
rustup target add x86_64-apple-darwin aarch64-apple-darwin
```

示例仓库预置 `macOS`、`Linux` 和 `Windows` 三个桌面预设；Android、iOS 与
Web 预设可直接在 Godot 的 Export 窗口创建。Godot 官方导出模板仍需按正常流程
安装，插件会读取预设中实际启用的架构并构建对应 Rust 目标。

导出包会保留场景所引用的 `.rs` 资源路径，但把源码正文替换为最小占位内容；
Cargo 构建目录和插件的编辑器专用 GDScript 不随游戏交付。实际逻辑已经编译到
项目模块中，运行时按资源路径绑定对应脚本类型。

编辑器工作流可在 `Cargo.toml` 中配置：

```toml
[package.metadata.godot-rust]
auto-check = true
build-before-play = true
```

`auto-check = false` 关闭保存后的自动检查，但仍可使用面板和菜单中的 Check。
`build-before-play = false` 明确跳过 F5/F6 构建门禁，应只在外部工具已经完成
构建并发布时使用。

## 安装到其他 Godot 项目

发布包用户只需把 `addons/godot-rust` 复制到自己的项目根目录，然后在
`Project Settings > Plugins` 中启用 `godot-rust`。如果项目还没有
`Cargo.toml`，插件会显示确认框，并执行：

```sh
cargo init --lib --vcs none --name godothub_project .
```

插件不会指定 Rust Edition，也不会覆盖已有 Cargo 文件或 `src/lib.rs`。
