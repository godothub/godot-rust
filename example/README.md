# Hello Rust

这个示例演示如何在 Godot 中编写、运行和导出 Rust 脚本。

## 仓库内运行

在仓库根目录构建并装配当前平台的开发插件：

```sh
python3 tools/stage_example_plugin.py
```

然后用 Godot 4.4 或更高版本打开本目录。示例已启用
`Project > Project Settings > Plugins > godot-rust`。顶部 `Project > Tools`
菜单中提供：

- `Rust: Project Status`
- `Rust: Check`
- `Rust: Build`

## 创建 Rust 脚本

1. 在场景树中选择节点，点击 Godot 自带的“挂载脚本”按钮。
2. 把语言切换为 `Rust`。
3. 把脚本保存到 `res://src/scripts/` 或其子目录。
4. 点击“创建”，插件会根据节点类型生成 Rust 脚本。
5. 保存脚本后自动检查代码，在底部 `Rust` 面板查看结果。点击 `Build` 应用修改。

`src/scripts/mod.rs` 是插件生成的编译入口，不需要手工添加 `mod`。插件只会
覆盖带有 `@generated by godot-rust` 文件头的索引，不会替换自行维护的
`mod.rs`。脚本可以放在多级子目录中。

编辑器底部的 `Rust` 面板显示检查和构建状态，并提供 `Check`、`Build` 和
`Clear`。Cargo 的错误、警告、错误码和主源码位置会显示在列表中；双击带有
项目源码位置的诊断即可打开对应 `.rs` 文件并跳到行列。自动检查失败时会保留
诊断；下一次检查成功后会清除已经过期的内容。

## 在 Godot 中编辑 Rust

打开 `.rs` 脚本后，Godot 自带的脚本编辑器会直接提供：

- Rust 2024 关键字、控制流关键字和基础数值类型着色。
- `//`、`/* ... */` 普通注释和 `///`、`//!`、`/** ... */`、
  `/*! ... */` 文档注释着色。
- 普通字符串、字节字符串、C 字符串和常见原始字符串的字符串区域着色。
- 编辑器原有的括号补全、行号、代码折叠、搜索、书签和多光标功能。
- `Ctrl+I`（macOS 为 `Command+I`）自动缩进。

自动缩进只处理选中的行；没有选区时处理整个文件。函数列表可跳转到
`#[script] impl` 中的方法。

部分复杂原始字符串的着色可能不准确，但不影响编译和运行。

## 从 Godot 连接信号

在场景树中选择信号源节点，打开 `Node > Signals`，按 Godot 原有流程选择信号
和目标节点并点击“连接”。目标节点挂载 Rust 脚本时，Godot 会直接打开对应的
`.rs` 文件，并生成可编译的类型化回调：

```rust
#[script]
impl Hello {
    #[func]
    fn _on_child_entered_tree(&mut self, _node: Option<ObjectRef<Node>>) {
        // TODO: Handle the connected Godot signal.
    }
}
```

回调参数会使用对应的 Rust 类型；Object 参数写成 `Option<ObjectRef<T>>`。
在生成的方法中填写处理逻辑即可，无需移动新建的 `#[script] impl`。
若某个参数类型尚不支持，编辑器会给出提示。

Godot 创建的最小脚本与平常的节点脚本写法一致：

```rust
use godot_rs::prelude::*;

#[script(base = Node2D)]
pub struct Player {
    #[export(default = 240.0)]
    speed: f64,
}

#[script]
impl Player {
    fn _ready(&mut self) {
        godot_print!("Player is ready; speed={}", self.speed);
    }

    #[func]
    fn double_speed(&self) -> f64 {
        self.speed * 2.0
    }
}
```

`#[script(base = Node2D)]` 对应 Godot 的节点基类，`_ready` 等生命周期方法直接
由引擎调用，`#[export]` 字段出现在 Inspector，`#[func]` 方法可由 Godot 调用。

`godot_rs::prelude::*` 是面向脚本的一行便捷导入，也可以改用普通 Rust 的显式
导入。结构体上的 `#[script]` 声明脚本类型；Godot 需要调用的方法所在 impl 再写
一次 `#[script]`。纯 Rust 辅助方法可以放在不带标记的普通 impl 中。

同一个类型可以按职责拆成多个 `#[script] impl Player`。生命周期、普通方法、
RPC 和由信号面板创建的回调可以放在不同的 impl 中，但不要重复声明同名方法。

## 字段、属性与方法

用 `#[export]` 在 Inspector 中编辑字段，用 `#[property]` 让 Godot 访问属性，
用 `#[func]` 或 `#[rpc]` 提供可调用的方法。其他字段和方法按普通 Rust 代码使用：

```rust
#[godot_enum]
enum MovementMode {
    Idle = 0,
    #[default]
    Walk = 1,
    Sprint = 2,
}

#[godot_flags]
enum Ability {
    Jump = 1 << 0,
    Dash = 1 << 1,
}

#[script(base = Node)]
pub struct Player {
    stamina_cache: f64, // 仅 Rust 可见

    #[property(default = 100, get = health, set = set_health)]
    health: i64, // Godot 可读写，但不显示在 Inspector

    #[property(default = 1, read_only)]
    level: i64,

    #[export(default = MovementMode::Walk)]
    movement: MovementMode,

    #[export(default = Ability::Jump | Ability::Dash)]
    abilities: Ability,
}

#[script]
impl Player {
    pub const MAX_HEALTH: i64 = 100; // 自动成为 Godot 脚本常量
    const CACHE_SLOTS: usize = 8;    // 仅 Rust 可见

    fn health(&self) -> i64 { self.health }

    fn set_health(&mut self, value: i64) {
        self.health = value.clamp(0, Self::MAX_HEALTH);
    }

    #[func(name = "heal")]
    fn restore_health(&mut self, amount: i64) {
        self.set_health(self.health + amount);
    }

    #[rpc(name = "sync_health", authority, reliable)]
    fn apply_network_health(&mut self, value: i64) {
        self.set_health(value);
    }
}
```

- `#[property]` 可由 Godot 读取或设置，但不显示在 Inspector 中。
- `#[export]` 显示在 Inspector 中，也支持从脚本访问。
- `read_only` 禁止通过 Godot 修改属性；Rust 内部仍可直接赋值。
- `#[func(name = "...")]` 和 `#[rpc(name = "...", ...)]` 只改变 Godot 中的名称，
  Rust 内仍使用原方法名，重构工具可以正常工作。
- 修改 `pub const` 后，执行 `Build` 才会更新 Godot 中可见的值。
- 自定义枚举和位标志保留未知整数值，因此读取未来版本或旧存档中的值不会产生
  非法 Rust 枚举。两种类型在 Script 与 Extension 项目中使用同一套定义。

### 打印日志

在 Godot 的 Output 面板中查看 `godot_print!` 输出的消息；警告使用 `godot_warn!`，
错误使用 `godot_error!`。`godot_debug!` 只在详细输出模式下显示，排查问题时可用
`godot --verbose --editor --path .` 启动项目。

## 全局类、自定义 Resource 与脚本继承

`class_name` 让 Rust 脚本进入 Godot 的全局脚本类列表。节点脚本可以直接用于
“创建节点”和类型提示，`base = Resource` 的脚本可以作为自定义 Resource：
首次 Rust Build 成功后，插件会在当前编辑器会话刷新这些类型，无需重启 Godot。

```rust
#[script(base = Resource, class_name = WeaponStats)]
pub struct WeaponStats {
    #[export(default = 10)]
    damage: i64,
}
```

Rust 脚本通过规范的 `res://` 路径继承另一个 Rust 脚本。派生脚本会获得父脚本
的 Inspector 字段、方法和信号；没有重写的生命周期方法沿用父脚本的实现：

```rust
#[script(
    base = Node,
    extends = "res://src/scripts/base_actor.rs",
    class_name = Player
)]
pub struct Player {
    #[export(default = 100)]
    health: i64,
}
```

父脚本需要位于同一个 Cargo 项目中，并使用相同的 Godot `base`；继承链中不能
重复声明字段或循环继承。重写方法后，使用 `call_super` 调用父脚本的实现：

```rust
#[script]
impl Player {
    fn _ready(&mut self) -> EngineResult<()> {
        self.call_super::<(), _>("_ready", ())?;
        Ok(())
    }

    #[func]
    fn display_name(&self, suffix: String) -> String {
        match self.call_super::<String, _>("display_name", (suffix,)) {
            Ok(base_name) => format!("[Player] {base_name}"),
            Err(error) => {
                godot_warn!("base display_name failed: {error}");
                "[Player]".to_owned()
            }
        }
    }
}
```

生命周期方法也通过同一个入口调用父脚本；`()` 表示没有参数或没有返回值。
普通父方法声明的尾随 `#[default(...)]` 也会生效，因此可以只传必需参数。
调用失败时会返回 `EngineResult` 错误，可用 `?` 交给 Godot 报告，或自行处理。

## 异步任务

使用 `spawn` 把工作安排到后续帧执行。任务运行在 Godot 主线程，可以调用
Godot API，也不要求 Future 实现 `Send`：

```rust
fn _ready(&mut self) -> EngineResult<()> {
    let owner_id = self.base().get_instance_id()?;
    let task = spawn(async move {
        next_frame().await;
        godot_print!("object {owner_id} reached the next frame");
    });
    let _task_id = task.id();
    Ok(())
}
```

调用 `TaskHandle::cancel()` 可取消任务；热重载或关闭项目时，未完成的任务也会
取消。任务中的 panic 只会结束该任务。使用 `async move` 把需要的数据交给任务，
不要捕获当前回调的 `&mut self`。

耗时计算或阻塞 I/O 可用 `spawn_blocking` 放到后台线程，Godot 对象和 API 仍需留在
主线程。取消等待不会停止已经运行的后台工作；热重载会等这些工作结束后再应用
新代码，因此后台任务应能自行结束。

## 热重载

修改脚本后点击 **Rust > Build**。构建成功后，Inspector 会自动刷新；已经运行的
游戏需要重新启动，才能使用修改后的代码。

给脚本的 `#[script(...)]` 添加 `tool` 后，脚本才会在编辑器中执行。tool 脚本可以
增删字段、方法、信号和生命周期回调，无需关闭场景；更新时不会重复执行 `_ready`。

已有导出属性默认保留当前值，调整字段顺序不影响这些值；新增字段使用默认值。
普通 Rust 字段会重新初始化。给需要保留的普通字段添加 `#[reload(persist)]`，
需要重置的字段添加 `#[reload(skip)]`。

更新失败时会继续运行原来的代码。先查看 **Output** 中的提示，再按情况处理：

| 情况 | 处理方式 |
| --- | --- |
| 字段改了类型，原来的值无法继续使用 | 使用新字段名，或添加 `#[reload(skip)]` 重置该字段，然后重新构建。 |
| `#[node]` 指向的节点缺失或类型不符 | 修正场景节点或字段路径。只修改场景时，更新会自动继续，无需重新编译。 |
| 修改了 Godot 基类、`tool` 设置，或删除了仍在使用的脚本 | 关闭并重新打开相关场景，或从节点移除脚本后再挂载需要的脚本。 |
| `spawn_blocking` 中的工作尚未结束 | 等待后台工作完成，更新会自动继续。 |

删除信号或接收方法、修改其参数后，相关连接会断开；按新接口重新连接即可。

## Extension Mode 原生类

直接注册原生类的项目使用简短的模式名：

```toml
[package.metadata.godot-rust]
mode = "extension"
godot = "4.4"
```

在 Extension Mode 中，用 `NativeClass` 定义 Godot 原生类，并注册方法、属性和
信号。下面的 `Mover` 为节点提供 `speed` 属性，并在 `_process` 中移动节点：

```rust
use godot_rs::engine::native_virtual;
use godot_rs::native::{Base, ClassRegistrar, NativeClass, NativeResult, NativeVirtualRegistrar};
use godot_rs::prelude::*;

struct Mover {
    base: Base<Node2D>,
    speed: f64,
}

impl Mover {
    fn process(&mut self, delta: f64) {
        let _ = self.base.translate(Vector2::new((self.speed * delta) as f32, 0.0));
    }

    fn speed(&self) -> f64 { self.speed }
    fn set_speed(&mut self, value: f64) { self.speed = value; }
}

impl NativeClass for Mover {
    type Base = Node2D;
    const CLASS_NAME: &'static str = "Mover";

    fn init(base: Base<Node2D>) -> Self {
        Self { base, speed: 120.0 }
    }

    fn register_virtuals(
        registrar: &mut NativeVirtualRegistrar<'_, Self>,
    ) -> NativeResult {
        native_virtual::node::_process(registrar, Self::process)?;
        Ok(())
    }

    fn register_methods(
        registrar: &mut ClassRegistrar<'_, Self>,
    ) -> NativeResult {
        registrar.property("speed", Self::speed, Self::set_speed)?;
        Ok(())
    }
}
```

`NativeClass` 还支持 Inspector Hint/Usage、属性分组、动态属性列表、属性回退值、
属性校验、自定义 `str(object)`、通知、类型化信号、RPC 元数据，以及抽象、虚拟、
暴露、仅运行时和自定义图标等 ClassDB 标志。常用 Godot API 仍通过
`self.base()`、构造函数、Singleton、Builtin 和 Utility 的生成接口调用。

## Extension Mode 热重载

点击 `Build` 后，编辑器会自动更新扩展类，保留已有节点和属性值；普通 Rust
字段重新使用 `init` 中的值。需要重新准备缓存或节点引用时，实现以下回调：

```rust
fn on_extension_reloaded(&mut self) -> NativeResult {
    self.rebuild_cache();
    Ok(())
}
```

该回调执行时，属性值已经恢复；`_ready` 不会重复执行。更新失败时继续使用
原来的代码。修改基类等需要重启的情况，编辑器会给出提示。

## rust-analyzer、外部编辑器与源码调试

首次配置 Cargo 项目时，如果对应文件不存在，插件会创建：

- `.vscode/settings.json`：连接项目 Cargo.toml 并启用 Clippy；
- `.vscode/tasks.json`：Cargo Check、Build 和 Test；
- `.vscode/launch.json`：CodeLLDB 与 GDB 附加配置。

已有文件不会被覆盖。VS Code、Zed 和 RustRover 会读取同一个 Cargo 项目及
`.cargo/config.toml` 中的 Godot API 选择。默认情况下，Rust 脚本遵循 Godot 的
“文本编辑器 > 外部”设置；未启用外部编辑器时仍可使用 Godot 内置脚本编辑器。
如需为 Rust 单独指定编辑器，可把 `GODOT_RS_EXTERNAL_EDITOR` 设置为可信编辑器
可执行文件的绝对路径。Godot 中的行列会一起传递。

调试脚本时先以开发配置执行 Rust Build，再从 IDE 附加到正在运行的 Godot
进程，即可在 `.rs` 回调中设置断点。热重载后若断点不再命中，重新附加调试器。
Release 导出使用优化构建。

## 方法默认参数与可变参数

用 `#[default(...)]` 为 `#[func]` 的末尾参数设置默认值。Godot 调用时可以省略
这些参数：

```rust
#[script]
impl Player {
    #[func]
    fn add_score(
        &mut self,
        amount: i64,
        #[default(1)] multiplier: i64,
        #[default(String::from("gameplay"))] source: String,
    ) -> i64 {
        let gained = amount * multiplier;
        godot_print!("{source}: +{gained}");
        gained
    }
}
```

第一个默认参数之后的固定参数都要提供默认值；生命周期回调和可变参数本身
不能设置默认值。默认表达式可能被多次求值，不要在其中修改场景、读写文件或
发送网络请求。对象参数的默认值只能是 `None`。

最后一个参数写成共享的 `&[Variant]` 时，方法会自动成为 Godot 可变参数方法：

```rust
#[script]
impl Player {
    #[func]
    fn record(
        &self,
        #[default(String::from("general"))] category: String,
        values: &[Variant],
    ) -> i64 {
        godot_print!("{category}: {} values", values.len());
        values.len() as i64
    }
}
```

`category` 之后的参数放在 `values` 中，每个值保留其 Godot 类型。

## Vector2、Vector2i、Vector3、Vector3i 与 Color

脚本可以像写 Godot 脚本一样直接使用 `Vector2`、`Vector2i`、`Vector3`、
`Vector3i` 和 `Color`。它们可用于普通 Rust 字段、`#[export]`、`#[func]`
参数和返回值，以及类型化信号：

```rust
#[script(base = Node2D)]
pub struct Mover {
    #[export(default = Vector2::new(240.0, 0.0), group = "Movement")]
    velocity: Vector2,

    #[export(default = Vector3::new(0.0, 1.0, 0.0))]
    target_position: Vector3,

    #[export(default = Vector2i::new(4, -6))]
    grid_cell: Vector2i,

    #[export(default = Color::rgba(0.2, 0.6, 1.0, 1.0), no_alpha)]
    tint: Color,

    #[signal]
    moved: Signal<fn(position: Vector2, tint: Color)>,
}

#[script]
impl Mover {
    #[func]
    fn advance(&mut self, position: Vector2, delta: f32) -> EngineResult<Vector2> {
        let next = position + self.velocity * delta;
        self.moved.emit(next, self.tint)?;
        Ok(next)
    }
}
```

`Vector2` 和 `Vector3` 提供 Godot 习惯的方向常量、点积、长度、归一化、线性
插值和常用算术运算；`Vector3` 还提供叉积。`Vector2i` 和 `Vector3i` 使用精确的
`i32` 分量，提供方向常量、点积与整数算术，适合网格坐标、单元索引和体素位置。
`Color` 提供 RGBA 构造、透明度修改、线性插值和逐通道相乘。字段保持公开组件，
例如 `velocity.x`、`grid_cell.y` 和 `tint.a`，不需要 getter 包装。`no_alpha`
只适用于 `Color`，用于在 Inspector 隐藏 Alpha 编辑。

浮点向量与颜色的分量类型为 `f32`，整数向量的分量类型为 `i32`。

导出的数学字段支持 Inspector 默认值、属性还原和场景保存恢复。Godot 中可用
`Vector2(...)`、`Vector2i(...)`、`Vector3(...)`、`Vector3i(...)`、`Color(...)`
直接调用相应的 Rust 方法并接收 Signal，不需要手工序列化数组或字典。

由官方 API 生成的 Godot 方法同样支持这些类型和 `String`。字符串参数以 `&str`
同步借用，返回值复制为标准 Rust `String`；向量和颜色通过精确的 ptrcall 原生
存储传递。因此 `base.set_position(position)?`、`label.set_text("Ready")?` 或
`grid.set_size(Vector2i::new(32, 32))?` 都不需要手写 Variant 转换。

## String、Inspector 与信号

脚本直接使用标准 Rust `String`，不需要包装类型。`#[export]` 的默认值和提示
会显示在 Godot Inspector 中，`#[func]` 的字符串参数与返回值可由 GDScript
直接调用，`Signal` 的参数名称和类型也会出现在 Godot 的脚本元数据中：

```rust
#[script(base = Node)]
pub struct Greeter {
    #[export(default = "你好", group = "Text", multiline)]
    message: String,

    #[export(default = "res://main.tscn", file("*.tscn"))]
    scene_path: String,

    #[signal]
    greeted: Signal<fn(message: String)>,
}

#[script]
impl Greeter {
    #[func]
    fn greet(&mut self, name: String) -> EngineResult<String> {
        let message = format!("{}，{name}", self.message);
        self.greeted.emit(message.clone())?;
        Ok(message)
    }
}
```

参数和返回值直接使用 Rust `String`，可保存到字段中或交给其他 Rust 函数，
无需手动转换 Godot 字符串。

String 导出字段会像其他 `#[export]` 字段一样随场景保存和恢复。`multiline`
用于多行文本，`file("*.tscn")` 用于带文件筛选条件的路径输入。尚未支持的
Variant 类型会在编译期报错。

## 调用 Godot API

`self.base()` 对应当前脚本所挂载的 Godot 对象。插件会按项目选择的最低
Godot 4.4、4.5、4.6 或 4.7 API 生成类型安全的 Rust 方法，并根据 ClassDB
继承关系自动提供父类方法：

```rust
fn _ready(&mut self) -> EngineResult<()> {
    let base = self.base();
    base.set_process(false)?;
    let was_disabled = !base.is_processing()?;
    base.set_process(true)?;

    let parent: Option<ObjectRef<Node>> = base.get_parent()?;
    godot_print!(
        "owner={}, disabled={}, has_parent={}",
        base.get_instance_id()?,
        was_disabled,
        parent.is_some()
    );
    Ok(())
}
```

方法参数和返回值保持 Rust 的精确类型，例如 `int32` 使用 `i32`、`uint64`
使用 `u64`、Godot `float` 使用 `f32`。普通对象使用 `ObjectRef<T>`，节点字段
可以使用 `NodeRef<T>`。引用的对象已被删除时，调用会返回
`EngineErrorKind::StaleObject`，此时应重新查找节点或停止使用该引用。

可调用的接口随项目选择的 Godot 版本变化。Script Mode 不提供需要操作原始指针
或引擎内部结构的底层接口。

### 单例、构造、Utility、Builtin、常量与引擎信号

除 Object 类方法外，官方 API 中其余可安全调用的入口也会按所选 Godot 版本
自动生成，并由 `godot_rs::prelude::*` 统一导入：

```rust
fn _ready(&mut self) -> EngineResult<()> {
    if Input::is_action_pressed("ui_accept")? {
        godot_print!("random value: {}", utility::randf()?);
    }

    let white = builtin::color::constant_white()?;
    let normalized =
        builtin::vector2::normalized(&Vector2::new(3.0, 4.0))?;

    let timer = Timer::new_godot()?;
    self.base().add_child_ex(timer.upcast::<Node>()).done()?;
    let timeout: Signal<()> = timer.signal_timeout()?;
    godot_print!(
        "color={white:?}, normalized={normalized:?}, signal={}",
        timeout.name()
    );
    Ok(())
}
```

- 单例使用 `Input::singleton()` 这类关联函数。
- 可实例化的 Object 类使用 `Timer::new_godot()`；RefCounted 类会返回
  `GodotRef<T>`，其他类返回 `ObjectRef<T>`。
- 全局函数位于 `utility`，例如 `utility::randf()`。
- Builtin 的完整官方接口位于 `builtin::<类型>`，包括构造、方法、运算符、
  成员、索引、键访问和常量。
- Builtin 实例还会获得 `Vector2BuiltinApi` 这类扩展 Trait，其方法统一使用
  `godot_` 前缀，避免覆盖 Rust 标准库和类型本身的同名方法。SDK 已经内联实现
  的数学操作可以直接使用；需要调用 Godot 的对应方法时，使用
  `value.godot_normalized()` 或 `builtin::<类型>` 模块。
- 引擎信号通过 `TimerSignals` 这类自动生成 Trait 提供类型化句柄，参数元组与
  官方信号声明一致。
- 全局常量位于 `global_constants`，类常量使用 `Class::CONSTANT`，Builtin
  常量通过 `builtin::<类型>::constant_<名称>()` 读取。

### RID 与引用计数对象

Godot `RID` 在 Rust 中写作 `Rid`。它是 RenderingServer、PhysicsServer、
NavigationServer 等服务器资源的不透明句柄，可以直接用于 `#[func]` 参数和
返回值、类型化信号以及生成的 Godot API：

```rust
#[signal]
canvas_ready: Signal<fn(canvas: Rid)>,

fn _ready(&mut self) -> EngineResult<()> {
    let Some(viewport) = self.base().get_viewport()? else {
        return Ok(());
    };
    let Some(world) = viewport.find_world_2d()? else {
        return Ok(());
    };
    let canvas = world.get_canvas()?;
    if canvas.is_valid() {
        self.canvas_ready.emit(canvas)?;
    }
    Ok(())
}

#[func]
fn echo_rid(&self, resource: Rid) -> Rid {
    resource
}
```

`Rid` 可复制、比较和作为 HashMap 键；`Rid::INVALID` 表示 Godot 的空句柄，
`is_valid()` 检查数值是否非零，`id()` 适合诊断输出。复制 `Rid` 不会延长
服务器资源的生命周期，使用前仍需确认资源未被释放。

上例中的 `find_world_2d()` 返回
`Option<GodotRef<World2D>>`，因为 `World2D` 继承自 Godot
`RefCounted`。持有或克隆 `GodotRef<T>` 会保持资源存活，所有引用都释放后才会
销毁资源，无需手动调用 `reference()` 或 `unreference()`。把它传给需要
`ObjectRef<T>` 的方法时，使用 `world.object_ref()`。

`ObjectRef<T>` 不会延长对象的生命周期，适合引用场景树管理的 Node。

### ObjectRef 与脚本方法

`#[func]` 也可以直接接收和返回带类型的 Godot 对象：

```rust
#[func]
fn choose_target(
    &self,
    target: Option<ObjectRef<Node>>,
) -> Option<ObjectRef<Node>> {
    target
}
```

这里的参数接受 `Node` 及其子类；`None` 对应 Godot 的 `null`。

普通 Godot 方法以 `EngineResult<T>` 返回错误。生命周期方法可以直接返回
`EngineResult<()>`，因此可以使用 `?`；也可以在 `ScriptResult<()>` 中使用
`?`，SDK 会把引擎错误转换为适合脚本回调的错误类别。

### 处理脚本错误

`ScriptResult` 返回的错误、引擎调用错误和未处理的 Rust panic 会显示在 Godot
调试器与 Output 中，包含脚本路径和方法名，便于定位错误。失败的方法向 Godot
返回 `null`。

某个节点连续三次回调失败，或发生 panic 时，该节点的 Rust 脚本会暂停执行，
其他节点不受影响。修正代码并成功热重载后可恢复运行，也可以重新挂载脚本。

## 获取场景节点

使用 `#[node("路径")]` 声明场景节点后，不需要在 `_ready` 中手动调用
`get_node`。路径使用 Godot 原生 `NodePath` 规则，字段类型同时限定节点类型：

```rust
#[script(base = Node2D)]
pub struct Player {
    #[node("%Sprite")]
    sprite: NodeRef<AnimatedSprite2D>,

    #[node("../Camera", optional)]
    camera: Option<NodeRef<Camera2D>>,
}

#[script]
impl Player {
    fn _ready(&mut self) -> EngineResult<()> {
        self.sprite.set_speed_scale(1.0)?;
        if let Some(camera) = self.camera {
            godot_print!("Camera object ID: {}", camera.get_instance_id()?);
        }
        Ok(())
    }
}
```

`#[node]` 字段在 `_ready` 之前自动赋值，无需手动初始化。找不到必选节点或
节点类型不符时，Output 会提示字段名、路径和要求的类型；据此修正场景或路径。
可选节点不存在时得到 `None`，类型不符时仍会报错。

## 构建与运行

点击 **Rust > Build** 手动构建，或按 **F5/F6** 让插件在运行前自动构建。
源码、依赖和构建设置没有变化时，会复用上一次成功的构建。

运行前构建失败时，游戏不会启动。在 Rust 面板查看错误，修复后再按 F5/F6。
仅在编辑器中构建失败时，现有脚本继续使用原来的代码。

Cargo 会自动下载缺少的依赖，无需提前运行 `cargo fetch`。
构建后的编辑器更新方式见[热重载](#热重载)。

## 导出游戏

直接打开 Godot 的 `Project > Export`，选择平台后使用原有的“Export Project”
或“Export All”即可。插件会在导出开始时自动完成以下操作：

- 根据 Godot 预设中的操作系统、架构以及 Debug/Release 模式调用用户本机 Cargo；
- 自动解析和下载尚未缓存的 Cargo 依赖，无需先执行 `cargo fetch` 或
  `cargo build`；
- 把编译完成的 Rust 代码随游戏一起打包，并使用 Godot 的签名设置。

Debug 导出使用 Cargo Dev Profile，Release 导出使用 Cargo Release Profile。
导出失败时，在 Rust 面板查看编译错误或工具链提示，修复后重新导出。

支持的目标包括 Linux x86_64/ARM64、macOS x86_64/ARM64/Universal、Windows
x86_64、Android ARMv7/ARM64/x86/x86_64、iOS ARM64 真机与 ARM64/x86_64
Simulator，以及 Web。Script Mode 和 Extension Mode 都支持这些目标。
Web 需要 Godot 的动态扩展模板。

桌面目标通常直接使用本机工具链。Android 需要 Android SDK、NDK 和对应 Rust
Target；iOS 需要 Xcode；Web 需要与目标 Godot 模板匹配的 Emscripten 工具链。
缺少链接器、标准库、模板或签名配置时会在导出阶段明确失败。macOS Universal
会分别构建两个 Rust Target 并合并为一个动态库；首次使用前确保两个标准库都
已安装：

```sh
rustup target add x86_64-apple-darwin aarch64-apple-darwin
```

示例仓库预置 `macOS`、`Linux` 和 `Windows` 三个桌面预设；Android、iOS 与
Web 预设可直接在 Godot 的 Export 窗口创建。Godot 官方导出模板仍需按正常流程
安装，插件会读取预设中实际启用的架构并构建对应 Rust 目标。

游戏包包含编译后的 Rust 代码，不包含 `.rs` 源码正文和 Cargo 构建目录。

编辑器工作流可在 `Cargo.toml` 中配置：

```toml
[package.metadata.godot-rust]
auto-check = true
build-before-play = true
```

`auto-check = false` 关闭保存后的自动检查，但仍可使用面板和菜单中的 Check。
`build-before-play = false` 关闭运行前的自动构建。使用此设置时，请先手动构建，
否则游戏可能仍运行上一次构建的代码。

## 安装到其他 Godot 项目

发布包用户只需把 `addons/godot-rust` 复制到自己的项目根目录，然后在
`Project Settings > Plugins` 中启用 `godot-rust`。如果项目还没有
`Cargo.toml`，插件会自动初始化 Cargo 项目：

```sh
cargo init --lib --vcs none --name godothub_project .
```

插件不会指定 Rust Edition，也不会覆盖已有 Cargo 文件或 `src/lib.rs`。
